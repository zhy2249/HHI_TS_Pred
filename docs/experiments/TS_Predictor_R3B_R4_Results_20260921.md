# R3-1/2 Class B 初步结果与 R4 CE 完整结果分析

日期：2026-09-21。唯一正式基线：Current。负 BD-rate 为改善。
所有百分数均先计算 Y/U/V 各自的 BD-rate，再按 6:1:1 加权。
带 `*` 的数值含授权的 QP22 anchor 暂代，不能标作完整实测结果。

## 1. 结论先行

- **R3-1 仍是主线：BCE 暂估 −0.075273%**，超过 −0.05% 目标，距 −0.08% 还有 0.004727 个百分点；尚未达到 −0.10%。评级为 **Promising（暂定，待四个 QP22 和外部运行身份核验）**，不是正式达标认证。
- **R3-2 BCE 暂估 −0.063619%**，也暂达最低目标，但平均收益不如 R3-1。评级 **Weak／保留分量对照**；其八序列改善多于 R3-1 的七序列，但收益幅度较小。
- **R4 没有一组改善完整 CE 平均相对 R3-1 的结果**。R4-3 与 R3-1 全部 28 个 RD 点相同，其余五组平均更差。本轮六组全部未通过事先冻结的扩展门槛，不建议铺开 R4 B/RA 长跑。
- R4-5 是最值得保留的诊断分支：五序列改善、去 PartyScene 后 −0.044064%，但 CE 均值与低质量区间均不如 R3-1。**它改善了稳定性的一些描述指标，尚未改善目标指标**。
- B 类的新收益不是仅靠填补制造出来的：完全排除 QP22，以实测 QP27/32/37 重建三点曲线，R3-1/2 的 B 仍为 −0.045677%/−0.044127%。但它们的 B 亮度 BD-rate 为正，收益主要体现在色度，不能解释成“亮度预测普遍更准确”。

本轮只读取结果并生成分析，没有修改 codec、宏、源工作簿、CSV 或启动编码。

### 2.2 算法与平均

\[
 BD_{611}(s)=\frac{6BD_Y(s)+BD_U(s)+BD_V(s)}8.
\]

各分量对 `log(rate)`–PSNR 曲线作 PCHIP 公共质量区间积分，不外推，不先加权 PSNR。
与工作簿 VBA `bdrate` 的独立数学复现比较，最大差 **2.97×10⁻¹³ 个百分点**；不依赖 Excel 的 BD 公式缓存是否刷新。

\[
 BD_{CE}=\frac{4BD_C+3BD_E}{7},\qquad
 BD_{BCE}=\frac{5BD_B+4BD_C+3BD_E}{12}.
\]

即 CE 七序列、BCE 十二序列等权，**不是 CE 类均值之和除二，也不是 B 与 CE 除二**。
组间“直接相对 R3-1”重新积分两条曲线，不把各自对 Current 的 BD-rate 相减冒充直接 BD-rate。

配置口径仍为 LB CTC 半帧；只有结果表，无法独立认证服务器真实帧数、配置、二进制、有效宏、重建 hash 或运行耗时可比性。
`pass` 仅是收到表格中的状态，不代替这些核验。

### 3.3 分量贡献与闭环反馈

| 方法 / 范围 | BD-Y | BD-U | BD-V | 加权 |
|---|---:|---:|---:|---:|
| R3-1 B* | +0.002041% | +0.030681% | −0.443356% | −0.050053% |
| R3-2 B* | +0.009175% | −0.029917% | −0.365384% | −0.042531% |
| R3-1 BCE* | −0.032468% | −0.046934% | −0.360448% | −0.075273% |
| R3-2 BCE* | −0.021335% | −0.045466% | −0.335479% | −0.063619% |

R3-1 BCE 三项加权贡献分别是 **−0.024351、−0.005867、−0.045056 个百分点**。
V 对净加权收益贡献约 59.9%，Y 约 32.4%。这些是 BD 指标的分量分解，**不是 Y/U/V 比特节省份额**。
各分量 BD 使用的 rate 都是整条码流总码率，而非该分量独立码率。

尤其重要：R3-2 只在 Y 上改 predictor，U/V 仍为 Current，但色度 BD 仍明显变化。
这与闭环搜索、分块、参考重建及总码率耦合相容；仅凭表格无法确定每条传播路径。
所以不能据“U 变差”直接推出“关闭 U predictor 就会修复”，也不能把 V 收益全归功于 V predictor。
R3-1/2 的 E 四点曲线逐序列相同，关闭色度没有解决 KristenAndSara 的损失，延续了此前结论。

### 3.4 是否仍主要靠 PartyScene？

R3-1 BCE 暂估中，PartyScene 占所有改善序列负收益幅度之和的 **41.5%**，低于旧 CE 的 57.8%；
Cactus、Johnny、BasketballDrill、BQTerrace 也贡献收益。去 PartyScene 后其余十一序列均值 **−0.039481%***。
因此已经不是“只在 PartyScene 有用”，但去掉它后仍未达到 −0.05% 工程目标。

损失侧较集中：KristenAndSara 与 BasketballDrive 占正损失幅度之和约 **61.8% 与 27.1%**。
它们值得作为失败机制样本，但不能从正式平均删除，也不能按序列名设置 codec 规则。
R3-1 的任意删一序列均值范围 **[−0.094790%, −0.039481%]***：方向尚稳，达标强度依赖样本组成。

### 3.5 QP22 暂代不是保守下界

填补完整 Current RD 点改变高质量端，也可能改变邻接 PCHIP 斜率；真实补点可能改善或恶化结果。
不能把“未测”当成“该实验不生效”，也不能把现有 BD 当 guaranteed lower bound。

完全去掉 QP22、重新用实测 QP27/32/37 构造三点 PCHIP：

| 方法 | B 三点诊断 | BCE 三点诊断 | B 的 BD-Y |
|---|---:|---:|---:|
| R3-1 | −0.045677% | −0.046736% | +0.026734% |
| R3-2 | −0.044127% | −0.042121% | +0.029223% |
| 固定 NoPred | −0.015488% | −0.026349% | −0.011238% |
| 固定 directional | −0.005026% | +0.031551% | −0.001930% |

这是**不同积分范围和不同拟合曲线的敏感性诊断**，不是四点主指标；不可混入正式 BCE 表。
它支持 B 中低码率范围有一定真实收益，也表明高质量范围对完整 BCE 达标仍重要。

额外压力情景：令全部缺失 QP22 的 PSNR 固定为 Current，只把其 rate 统一改为 Current 的 ±0.5%。

| 假设的缺失 QP22 rate 变化 | R3-1 BCE | R3-2 BCE |
|---|---:|---:|
| −0.5% | −0.096684% | −0.080098% |
| 0，即当前暂代 | −0.075273% | −0.063619% |
| +0.5% | −0.053956% | −0.047213% |

这**不是预测、置信区间或上下界**，真实 PSNR 也会变化；仅展示补点敏感程度。
R3-1 若要从暂估走到 −0.08%，四条缺点序列各自完整 BD 的平均变化只需 **−0.014180 个百分点**；
跌回 −0.05% 则对应这四条平均恶化 **+0.075820 个百分点**。
R3-2 到 −0.08% 需要三条缺点序列平均再改善 **−0.065523 个百分点**。
这些是总平均的代数敏感性，不是缺失 QP22 本身需要达到的码率变化。

**R4-1/2：两类分支不能简单删掉一种。**
R4-1 保留的是 R3 选择的 identity 分支，不是全局固定 NoPred；R4-2 仅保留非 identity 分支。
两者分别删掉另一分支后，完整 CE 都变差，且去 PartyScene 后都退化。
R4-2 在 KristenAndSara 很好，但损伤 BasketballDrill、RaceHorsesC、FourPeople、Johnny。

R4-1+R4-2 的 BD 也不能与 R3 作加法分解：闭环 RDO、重建与后续决策已经改变。

**R4-3：没有可观测增量，先查活动，不再长跑同一变体。**
28/28 个码率及 Y/U/V PSNR 点与 R3-1 完全相同，三个质量区间也一致；其中 25/28 点不同于 Current。
所以收到的数值不是整组 Current，但仍不能凭表格确定实际运行的是 R4-3，或断言码流 bit-exact。
可能是 rescue 没有产生有效 remapping 改变、改变未影响最终决策，或服务器模式/结果归属问题；需远端 banner、二进制/源码版本及 rescue/实际映射差异计数区分。
这是“本版未显示增量”，不是已证明所有 guard rescue 在数学上无效。

**R4-4：方向加权修好一个局部，损伤另一个。**
RaceHorsesC 改善，但 Johnny 从 −0.138684% 变成 +0.154658%，E 类转为 +0.067039%。
说明方向一致性并非可靠的通用替代依据；当前权重版本应停止扩展，不根据这七序列再扫描权重比例。

**R4-5：不是全面失败，但尚不能替代 R3。**
RaceHorsesC 从 +0.001353% 到 −0.156115%，KristenAndSara 从 +0.139408% 到 +0.068652%，BasketballDrill 也略好。
代价是 PartyScene 从 −0.468990% 到 −0.192353%，BQMall 从 +0.018316% 到 +0.141852%，Johnny 收益减少。
其 CE 中位数 **−0.097398%** 优于 R3-1 的 −0.082512%，标准差 **0.123816** 小于 0.191358，PartyScene 负收益份额降至 **28.8%**。
这些支持“收益更分散”的描述，不能抵消它的目标平均退步及低质量失效。
完整 CE 的 Y 也从 R3-1 的 −0.057117% 减弱到 −0.028577%；更强的 V 收益并没有带来整体胜出。

**R4-6：收益更集中、坏例更坏。**
PartyScene 略胜 R3-1，但 BQMall 退化 +0.307282%，FourPeople 由负转正，E 总体转正；去 PartyScene 后 +0.057192%。
本版 signed-plane 加选择器不值得增加完整 B/RA 成本；不能据此否定所有 signed predictor，只否定本版推广。

## 5. 稳定性、统计不确定性与效应大小

按序列作 10,000 次 bootstrap，固定随机种子；CI 是对现有序列组成的描述性重采样。
不是 coefficient 独立采样，不把 28/48 个 QP 点当独立序列；未对多次实验选择作多重比较校正。
R3 区间还**不包含缺失 QP22 的不确定性**，CE 已重复用于设计，不能视为独立测试集。

| 指标 | 平均 | 中位数 | 标准差（百分点） | 95% bootstrap CI |
|---|---:|---:|---:|---|
| R3-1 BCE* | −0.075273% | −0.063189% | 0.153412 | [−0.166908%, −0.000798%]* |
| R3-2 BCE* | −0.063619% | −0.054362% | 0.127436 | [−0.137471%, +0.001260%]* |
| R3-1 CE | −0.093288% | −0.082512% | 0.191358 | [−0.235722%, +0.025639%] |
| R4-5 CE | −0.065248% | −0.097398% | 0.123816 | [−0.142636%, +0.025062%] |
| R4-5 直接对 R3-1 CE | +0.028493% | 0 | — | [−0.061650%, +0.130482%] |

R3-1 BCE P10/P90 为 **−0.173140%/+0.056933%***；R3-2 为 **−0.170909%/+0.060923%***。
R4 六组相对 Current 的 CE 区间全部跨零；不能把所有负均值都解释为已确认收益。
R3-1 的暂估 CI 上界刚小于零，也不能据此宣称“显著”：补点误差、序列非随机性与重复筛选未被它覆盖。

四点 cubic 敏感性：R3-1/2 BCE 为 **−0.067712%/−0.054076%***；R4-5 CE **−0.052743%**，R3-1 CE **−0.085046%**。
主线次序与“R4 未超过 R3-1”不依赖 PCHIP/cubic 选择，但 −0.08% 等细门槛仍敏感；正式口径固定 PCHIP，不择优挑算法。

工程效应仍是百分之零点零几：目前证据支持 R3-1 继续验证，不支持忽略 decoder 复杂度或因此宣布成熟工具。
CSV 中有 mean、median、stddev、P10/P90、删一序列、质量区间、QP 实测变化等完整明细。

## 6. 冻结规则下的决定与下一步

R4 原定准入同时要求：对 Current CE 负均值、非正中位数、去 Party 非正；直接对 R3-1 负均值、非正中位数；共同低质量段不更差、高质量仍有收益；外部身份与有效活动可验证。

| 组别 | 评级（适用范围） | 决定 |
|---|---|---|
| R3-1 | **Promising，暂定** | 先补四个 B QP22；保持现有算法和运行版本，作为主线 |
| R3-2 | **Weak** | 补三个 B QP22，保留 Y-only 对照；不能凭暂估认定其应替代 R3-1 |
| R4-1/2 | **Negative，作为 R3 替换／简化方案** | 保留消融证据，不推广；不据此删除 identity 或幅值候选 |
| R4-3 | **Negative，增量价值未显示** | 核对远端活动及版本，不追加同版长跑 |
| R4-4 | **Negative，本版扩展** | 方向加权没有解决目标问题，暂停 |
| R4-5 | **Weak，诊断备选** | 保留模型回看思路，但未通过完整均值与低质量门槛，不直接铺 B/RA |
| R4-6 | **Negative，本版扩展** | 有局部优势但更集中、更不稳定，暂停 |

没有为了选一个 R4 赢家而放宽事先规则。负评级指当前版本的增量推广价值，不等于它对 Current 每条序列都退化。

后续优先顺序：

1. 补齐 R3 七个 QP22，重新计算完整 BCE，核验远端宏/banner、源码/二进制、实际半帧、解码 hash。此时再判断 −0.05/−0.08/−0.10% 是否达成。
2. 保持 R3 既定后续测试不变；未取得本轮 RA 数据前，不从旧 NoPred RA 结果推断 R3 可泛化到 RA。
3. 若需要设计下一轮，优先研究 **R3 与 R4-5 选择质量为何失配**，而不是继续堆候选公式：BQMall 是共同坏例，RaceHorsesC 是 R4-5 真改善例，PartyScene 是收益保护例，KristenAndSara/BasketballDrive 是分量反馈例。不能据序列标签写规则。
4. 建议先取得已有聚合活动计数：相对 Current/R3 的实际 remapping 差异、identity/幅值分支、回看专家选择、rescue 有效次数、分量/TU 尺寸覆盖及 decoder 开销。R4-3 尤需区分“被提议”“被接受”“实际改变 remapping”。这些仍只用于机制诊断，最终 TS 块的活动统计不代替闭环 RD 结果。
5. 新规则须在完整 R3 数据后预先冻结，再用未参与设计的配置/序列验证；不按这次七序列逐个挑模式，也不因多个 R4 未胜出而无约束搜索阈值。

仅有码率/PSNR 表，不能计算 CG Oracle、adaptive capture ratio η、CG persistence、TU-size 收益或预测误差分布。
本轮是真实闭环方法的结果，避免了“固定 anchor 最终 TS 集合”作为主评价的选择偏差；但研发集合反复使用、源结果身份和补点不确定性仍然存在。

```bash
python3 scripts/ts_r34_results_analysis.py --impute-r3-b-qp22
python3 -m unittest discover -s scripts -p 'test_ts_*analysis.py'
```

补齐后应改用无该参数的严格命令，并为新版结果指定新输出目录，保留本次快照：

```bash
python3 scripts/ts_r34_results_analysis.py --out runs/ts_r34_results_complete
```
