# R14 部分结果：输出相似性与状态更新机制核验

日期：2026-10-24。范围：结果分析、数据登记和源码只读核验；未修改编码算法，未运行序列编解码。
当前本地源码：`6f0eb43`，编号 `compact-15-v1`，算法 `R14-NF-168-v3`。

## 1. 当前判断

**部分方案的动态增量确实不明显，尤其是 PAIR2 的 E 类结果；但现有数据不能证明“状态几乎不转移”。**
目前收到的是最终码率和 PSNR，没有服务器的状态计数。必须区分以下几层：

1. 没有有效反馈位置；
2. 有效位置上所有权重档选择相同 predictor；
3. predictor 不同，但整数反馈 cost 相同，因此不更新；
4. 微状态更新，但 PAIR2 的输出权重不变；
5. 权重变化，但 predictor 或实际 remapping 不变；
6. 编码动作变化，但对最终 RD 的作用很小，或在打印精度下不可见。

源码中第 2～5 层都有明确成因。另一方面，NONE 动态组相对初始固定方法已有约 63%～80% 的上报点不同，
不能把整轮解释为完全没有活动。当前评级为 **Weak：动态选择的稳定增量尚未证实，状态活跃度尚未测得**。
不据此增加档位、放宽更新或选择新的阈值；先用已经实现的活动统计定位主要损失环节。

## 3. “相同”需要先明确对照

以下相同均指上报精度下 `(总码率,Y PSNR,U PSNR,V PSNR)` 四元组完全相同，**不是码流 bit-exact**。
当前文件按四位小数报告 RD；没有码流哈希，不能排除更小的变化。

### 3.3 固定 R14-7 的特殊情况

固定 near-only 的 **20/20** 点与 Current 完全相同。它没有动态更新，因此不能用于证明动态状态没动。
本地评分公式也不恒等于 Current：现有设计核验已给出 near-only 选择非 Current 的反例。
目前只能说它在这批结果上的可见收益为零；应核对启动模式和作用计数，再判断是否值得保留该固定分支。

## 5. 源码为何可能使更新不明显

### 5.1 状态未被错误地逐 CG 清空

`CoeffCodingContext` 在 TU/分量入口初始化状态；CG 入口保存快照，RDOQ 选择全零 CG 时恢复完整微状态。
非零 CG 保留更新。Writer 在最终幅值已知后 commit，Reader 在恢复真实幅值后 commit。
状态更新不依赖 `TS_R14_STATS`；关掉统计不会关掉学习。

核验位置：`ContextModelling.cpp:150`、`ContextModelling.h:640`、`QuantRDOQ.cpp:1458`、
`CABACWriter.cpp:4107`、`CABACReader.cpp:4652`。本次未发现每 CG 错误初始化的证据。

### 5.2 严格优势才更新，整数反馈容易平局

设档位 r 的 predictor 为 p_r，当前最终幅值 a。有效反馈要求 dynamic、a>0、n≥3，且 near/far 均有非零样本。
n 是 `{L,U,D,LL,UU}` 的非零物理位置数，重复幅值仍分别计数。

对有效反馈，源码保证：

\[
s'\ne s\quad\Longleftrightarrow\quad
C(f(a,p_r))>\min_t C(f(a,p_t)).
\]

原因是当前档位一旦属于最小 cost 集合，距离为0，平局必定留在当前档位。
这里反馈不是 CABAC fractional bits，而是整数 `syntaxCost`：

\[
C(f(a,p))=\begin{cases}
1,&p=a>1,\\
C(a+1),&p>a,\ p>1,\\
C(a),&\text{其它}.
\end{cases}
\]

对固定 a，反馈最多区分这三种值。所有档位低估时完全无法区分；没有精确命中且 C(a)=C(a+1) 时，
即使实际 remapping 不同也不会更新。例如 C(2)=C(3)=3，C(6)=C(7)=5。
这证明反馈信号存在压缩，但**不能从公式确定真实视频中压缩了多少有效位置**。

prepare 的评分是 `K*N(p)+r*F(p)`，N/F 使用 R13 KeepHit-168 的 ±1 机会评分；
commit 使用固定最终 a 的 remapping 整数成本，两者目标不同。这是设计选择，不自动属于实现错误。
把 KeepHit 评分直接复制到反馈也不能未经验证就称为更准确。

位置：`TsR14Prediction.h:23,81,90`、`TsR13Prediction.h:24`、`TsFixedPrediction.h:623`。

### 5.3 状态、权重和 predictor 不是一一对应

各候选评分是 r 的线性函数，但最优 predictor 关于 r 是分段常数；多个档位可以拥有相同 winner。
NONE 向目标只走一步，可能仍停在同一 winner 区间。PAIR2 另有 `r=floor(s/2)`：
向上时只有原 s 为奇数才改变权重，向下时只有原 s 为偶数才改变权重。
equal 初态首次向下、zero 初态首次向上仅改变相位；half 的首次上下响应也不对称。
它不是所有情况下都“固定要求两次确认”，跨边界后反向一步可能立即回去。

本次用已有纯函数 query 核验了一个机制例子（非视频，不是服务器频率）：

`H=(2,3,10,10,10), K=2` 得到各档 winner `[3,10,10]`。

- a=6：p=3/10 分别映射6/7，但 cost 都为5，状态不更新。
- a=9、NONE 的 r=2：目标为0，只走到1；权重改变，但该邻域 winner 仍为10。
- 同一事件、PAIR2 的 s=5：只到4，权重仍为2；再一步到3才改变权重，而该邻域 winner 仍为10。

这说明“输出没变化”无法定位是哪一层不起作用。

### 5.4 生效位置、剩余历史长度与闭环反馈

pure-bypass 位置不真正 remap，但仍可反馈；TU 后部更新可能已没有后续有效位置。
小 TU、n<3、全零 CG 回滚也会限制学习，但当前 RD 文件没有 TU 尺寸/CG 数，不能报告尺寸结论。
普通 TS-RDOQ 的 predictor-driven `allowUp` 又在 regular-bin budget 判断之前产生；
所以 bypass 位置“实际不 remap”也不保证 predictor 对量化候选和 RD 完全没有作用。

此外，当前 a 来自已经受 predictor 影响的 RDOQ；候选评估在同一个 a 上进行，
并未重做其它档位的量化和 RD。若当前 predictor 使 a 更容易命中自身，反馈可能偏向已选路径。
这是需要实测的闭环偏置假设，不应把“即时 fixed-q 最优”直接等同于下一位置或完整编码最优。

## 6. 下一步：先定位作用在哪一层消失

本轮没有修改算法，也不建议立刻追加一轮参数扫描。优先保留现有编码进度、排除并重核模式2身份，
补齐结果后再判断完整 CE。另取少量代表内容开启**已有** `TS_R14_STATS=1`，无需先新增统计代码：

- E类保持初态：Johnny 的 R14-1/10、R14-4/13；
- C类已有响应：BasketballDrill 的上述模式；
- 内容退化对照：BQMall，避免只观察收益序列；
- 每个先取 QP27 和37；保持匹配输入/帧范围，短帧只用于机制定位，不能替代完整 RD。

以下是需要的分层指标，按 component、实际 W×H、CG 数、n 和 CU QP 分类：

| 要回答的问题 | 已有字段或计算 |
|---|---|
| 是否有足够反馈机会 | eligible_count / coeff_count；tu_valid_sum / tu_count |
| 权重是否无法改变动作 | same_winners_count / eligible_count |
| winner 不同却仍保持 | (neutral_count − same_winners_count) / eligible_count |
| 状态是否真的更新 | state_change_count / eligible_count |
| 是否只动相位 | phase_only_count；weight_change_count / eligible_count |
| 学习是否改变 predictor / 实际映射 | p_vs_initial_weight；actual_remap_vs_initial_weight / actual_remap_nonzero |
| 更新是否太迟 | tu_first_weight_event_sum、tu_remaining_valid_sum、tu_with_weight |
| 对下一有效位置是否有用 | next_gain_sum 及正/零/负计数、next_actual_remap_changed |
| 搜索内更新是否被整体清零撤销 | 独立 TRIAL 表的 rolled_back_state_count |

`feedback_cost_tie_count` 表示多个最优档位，**不等于不更新**；当前档位不在最优集合时仍可更新。
`p_vs_current`、`tu_with_pdiff` 包含初始固定评分本身的作用，不能代替相对初始档的学习增量。
`g_next` 仍是同轨迹固定 q 的整数 cost，不是 CABAC 节省或 BD-rate；最终 Writer 和 RDOQ trial 分开报告。
统计开销不用于复杂度计时。若服务器已有这些日志，直接用 `scripts/ts_r14_activity.py` 解析，无需重跑。

后续决策应由统计区分：

- same-winner 占绝大多数：更多档位难以创造有效动作，应降低状态模型优先级；
- 不同 winner 但反馈几乎全平局：优先核验反馈代价的信息量，而非让状态随机移动；
- 状态常动但权重/映射不动：重点检查 PAIR2、重复 winner 区间和 TU 内剩余作用长度；
- 映射已经变化但 g_next/闭环无益：问题是可预测性或 RD 目标，不是“转移不够”；
- 少数序列有用、其它序列退化：暂不判 Promising，不以本轮缺点子集选最优参数。
