## 4. P1：定位Johnny32 POC16的首次真实搜索分叉

### 4.1 先区分三个“首次”

必须分别记录：

- **首次数值分歧**：某个TS trial的p、q、bits或局部J不同，可能随后被淘汰且无后效。
- **首次控制／历史分歧**：候选被跳过、枚举顺序改变、临时最优改变、分割成本或历史写入不同。
- **首次保留结果分歧**：最终CU树、编码模式、重建或语法不同。

目标不是报告最早一个p不同就结束，而是连接上述事件，并说明哪一条路径最终保留到POC16输出。搜索差异既可能是合理的启发式反馈，也可能是实现问题；需要证据才能分类。

### 4.2 入口相同性不能仅凭前缀码流推定

继续从POC0编码到16，不能把第16帧截出作为新I帧。复用相同输入、原LBeu配置、scope=all及一致构建；确认0–15前缀仍逐字节相同。

在POC16帧入口与每个CTU／根CU入口，保存显式、稳定的摘要：原图和已解码参考图像hash，实际QP/分量lambda，slice与工具flags，CABAC入口context，重建邻域，搜索历史／模式缓存及其清零边界。区分解码器可恢复状态和编码器私有搜索状态。

如果帧或CTU入口的私有状态已经不同，先追其写入来源；不要强称后面的trial是同入口，也不要无条件清空缓存把问题隐藏掉。某类SBT历史在根CU/CTU入口清零的源码事实，不能推导所有历史都没有跨帧影响。

### 4.3 两层限流观察，而不是全程序打印

**第一层：POC16全帧粗摘要。** 每CTU／根CU仅输出入口/出口、最终划分与重建hash，以及测试/跳过的模式数量、原因计数。找到第一个不同区域。

**第二层：该区域的细轨迹。** 覆盖其共同父节点、所有相关兄弟和落选候选，而非只记录最终TU。必要时扩到紧邻前一个区域，以捕获帧内重建／历史输入。

建议新增只读记录如下（这是后续待实现的字段合同，不是声称已有命令）：

| 字段组 | 至少包括 |
|---|---|
| 稳定事件键 | sequence、QP、POC、CTU地址、分量/树类型、area(x,y,w,h)、分割路径、父事件ID、候选类型及本节点出现次数 |
| 入口摘要 | 原始/预测/残差/重建邻域hash、上下文hash、QP/lambda、regular-bin预算、相关历史键值 |
| TS量化 | H、C0/EQ/SP的p、实际选用p、round/min/up及allowUp、候选列表、选中q/CG清零、实际入口下D/R/J |
| 决策 | 当前候选成本、比较对象成本、临时bestTU/全局bestCU是否更新、实际分支谓词和参与比较的阈值 |
| 后效 | 哪个缓存/历史/BT或TT成本被写入、后续哪个事件读取、哪个候选因而被省略或新增、最终节点结果 |

分支出现差异后，不能继续按“第n条日志”硬配对；使用共同祖先和稳定键标记新增／缺失事件。浮点值保留hex或足够精度，不能只打印两位小数。hash只覆盖确定语义字段，不能对含指针或padding的结构体直接做memcmp/hash。

限流器达到上限时输出明确的truncated标志；被截断的轨迹不能用来证明“没有分叉”。只读观察不推进context、不改变m_testedLevels、cache、真实q或候选枚举顺序。

### 4.4 重点源码入口与需要记录的判断

以下是已经确认存在的路径，不是已确定的实际触发原因：

| 位置（source/Lib/EncoderLib/） | 下一步必须记录 |
|---|---|
| `InterSearch.cpp`约7611/7837；`IntraSearch.cpp`约4090/4167 | TransformSkipFast开关、当前临时bestTU的mtsIdx和CBF、是否退出后续transform组；同时记录邻近的CBF=0提前退出，不能全算TSFast作用 |
| `EncModeCtrl.cpp`约1969/2079与1914 | 写入BT/TT成本的事件及其是否最终获胜；后续TT剪枝实际读到哪个值、阈值和结果 |
| `EncCu.cpp`约4094/4286与558 | SBT/transform历史更新条件、键值、读取者与重置范围；不要因为候选落选就假设历史未更新 |
| `EncCu.cpp`约453及新探针调用点 | CABAC/候选状态保存恢复是否确实相同；只有观测到不应保留的差异才调查泄漏 |

本次只读源码复核确认：InterSearch在后续transform组入口可因临时bestTU为TS而break；EncModeCtrl先保存分割成本，另处使用它进行TT剪枝。因此落选TS trial改变后续搜索在结构上是可能的。

### 4.5 一次只控制一个已定位的搜索因素

先保留原配置的EQ/SP基线。若轨迹显示TSFast门控是首个有效分叉，才对EQ与SP**同时**禁用TransformSkipFast并重跑同一0–16前缀。配置应明确记录为诊断配置，不能与原CTC Current计算正式收益。

若TT剪枝是首个分叉，单独控制实际相关的TTFastSkip条件。不要同时关闭TSFast、TT剪枝和SBT历史后声称已经定位某一项。若需要强制两边在该节点使用相同候选列表，采用独立标识的编码器搜索诊断，保留完整上下文恢复及解码验收，不将它注册成正式算法。

对每一对记录：

1. 干预是否实际改变了目标谓词，而非仅设置了一个无作用开关；
2. 原先分叉的节点是否仍出现、是否推迟或迁移；
3. 最终CU树、before_dbf及final SSE/hash和帧bits的EQ/SP差额；
4. 是否引入另一条更早的分叉，若有则重新解释。

若关闭某门控后差异消失，只能说明该搜索设置参与本前缀差异的形成；它不证明门控是bug，也不证明关闭后整体编码效率更好。差异未消失也不自动排除其局部作用。

**P1完成标准：**至少获得一条“同入口或已解释入口差异 → 指定trial差 → 指定历史/分支改变 → 后续保留决定/重建改变”的链。若尚未连接，状态保持为未定位，不以更大的trial总和替代。

## 5. P2：分解Johnny32首帧的Y→UV路径

这里比较C0与SP，不能用首帧码流相同的EQ/SP替代。最新首帧分量消融已经完成，先复用，不重复验证all=luma、chroma=C0。

### 5.1 从已有stage/tile缩到第一个实际色度块

优先查before_dbf的U损失tile，再定位编码顺序中最早不同的UV块；同时定位它依赖的Y区域。若两条轨迹划分不同，以最小共同父区域比较，不能把不同面积TU的SSE直接相减。

补充记录必须是实际启用值：

- 当前Y重建、色度预测及残差hash、最终重建和CBF；
- LMCS相关slice/picture/CTU gate、邻域Y摘要、chromaScale、实际分量QP与lambda；
- CCLM/CCCM是否真的获选、使用的Y参考范围与预测hash；
- 是否在UV求值之前已经发生Y划分／候选列表／共享context差异；
- JCCR、跨分量模式及色度量化路径的实际状态，不能只记总配置开启。

按以下顺序判读：输入Y不同而UV模式/scale相同，检查预测样本；scale先变，检查缩放与lambda；划分/模式先变，检查对应RD竞争。多条路径可以并存，不强行只选一个原因。

### 5.2 需要隔离时优先用私有buffer的单块探针

例如固定同一色度模式与其他输入，仅替换相应的Y参考样本，观察预测、残差和局部RD；或固定scale检查结果。该探针仅在私有buffer/context上计算，不写回正式重建或码流。

**不能把一条轨迹的Y重建/LMCS scale硬塞进另一条正式编码路径，却让decoder按正常方式推导。**这可能破坏编解码一致性。真正的工具关闭消融必须使用双方可一致恢复的配置，并在C0/SP双方同时改变同一选项、独立解码。

P2只需先解释首个可追踪块，不要求一轮将全部跨分量工具关闭。首帧结论仍限于首帧，不外推后续300帧占比。

## 6. P3：把合并滤波stage拆成可判读的观察

### 6.1 Johnny27 POC8：先分离CCSAO与联合裁剪

当前after_sao_bif为待clip buffer；after_ccsao_clip同时包含CCSAO和联合clip。下一步新增只读观察：CCSAO前、CCSAO后但clip前、联合clip后，并记录实际CTU/分量开关、分类/offset和原图hash。

必要时在私有副本上计算“clip-only”结果，避免把已有SAO/BIF越界裁剪的作用全算成CCSAO。未裁剪buffer的误差明确标为raw SSE，不作为合法重建视频质量结果。

已有V SSE：C0为3671075→3563881，EQ为3650689→3528240，SP为3646796→3585402。三条轨迹该阶段都获益；SP获益少，而不是自身误差增加。引用此事实时保留联合clip口径。

### 6.2 K&S32 POC0：分离普通ALF与CCALF

在真实调用顺序中记录普通ALF前后、CCALF前后，附每分量的实际启用、filter/APS标识与参数摘要。不能仅凭after_alf扩大U差异就锁定CCALF。

POC0为I帧，本工程LFCCCM的非I门控使它不能解释该首帧的首次损失。后续B帧则不同：LFCCCM在ALF前可改变训练target，在后面再加回correction。分析B帧时应覆盖target修正与correction加回两处，不只看after_lfcccm。

### 6.3 统一报告自身改善与跨方法差异

对相同原图定义G_m=D_in,m−D_out,m。则两方法S与R的误差差距满足：

`(D_out,S−D_out,R)−(D_in,S−D_in,R) = G_R−G_S`。

因此跨方法差距扩大可能只是S获得较少改善。报告同时给出每条轨迹自身G以及跨方法差距，不能混为一项。

固定参数换输入／固定输入换参数的回放可帮助区分输入分类和参数训练作用，但必须标为只读反事实；不形成真实码流，也不是全段工具开关消融。继续用raw SSE和hash，不能只凭四位小数PSNR寻找首次变化。

## 7. 低幅值假设如何继续检查，而不是被过早否定或接受

保留两个不同假设：

- H1：最终获选TS的低幅值映射／量化本身损失。
- H2：低幅值让被淘汰的TS候选成本敏感，改变临时best/剪枝/历史，再影响最终非TS及UV路径。

Johnny32当前证据削弱“H1直接发生于最终UV TS”的解释，却仍允许H2。后续重点记录P1已定位分叉所在的trial，不先对数千万搜索位置做一个不分层均值。

建议分层字段：POC0/后续帧、分量、入口轨迹C0/EQ/SP、CU/TU尺寸、获选/落选、CG实际清零、预测分歧与否、普通舍入A=0/1/2/≥3、最终q、舍入epsilon区间、固定/原生候选、allowUp、ΔD/λ、ΔR、ΔJ/λ。

A与epsilon来自编码器源值，只能用于诊断；不得进入decoder隐式预测。若当前诊断schema没有某字段，应标为待新增，不从最终q反推出A或epsilon。反馈中q内生性不能靠增加更新频率消除。

每条局部配对检查 `ΔJ/λPerBit = ΔD/λPerBit + ΔR_bits`；lambdaPerBit按当前实现为m_dLambda×32768，沿用已有诊断定义。D为内部RDOQ域，不是像素SSE；必须逐位置归一后汇总。固定候选／原生候选分开，实际CG全零结果不是每个probe重做的替代CG决策。

报告总和、每配对均值及唯一节点/重复trial数量。不能把11,701,504次搜索位置当成独立图像样本；不能跨不同轨迹直接相减J总和；不能用首帧超大搜索人口掩盖后续帧反向结果。增加幅值桶只用于解释，不因此立即制定幅值/色度/QP禁用门槛。

## 8. P4：何时延长前缀，以及怎样不破坏参考历史

- Johnny27：已有本地0–16并未复现全段V净损失，而服务器POC17–32均值已为负。P1/P3具备可用工具后，可按同前缀延长至33帧并限流观察POC8、16及17–32。
- Johnny32：先解决POC16权重首次分叉。再解释原300帧中136–215的V损失段，重点168–183；需要前缀到至少184才观察到该段，不能跳过前史或把窗口首帧当I帧。首分叉链不必自动等于中段全部损失链。
- Johnny37：当前只有首帧本地探针，无服务器逐帧日志。先获取既有服务器日志；若确实没有，再从POC0渐进延长、定位第一次持续负差，之后才开重型探针。QP37的CCALF门控与QP32不同，记录实际flags，不能迁移QP32结论。
- 正向对照保留FourPeople等已有有利内容。在确有机制修改时才做小规模配对验证，避免只在Johnny上选择参数或牺牲其它内容。

长前缀优先使用轻量frame/stage观察，详细trial仅限目标POC/区域。无checkpoint机制时不能假定能够无损resume编码到任意POC；从头重跑与marker续跑是不同概念。

## 10. 新观察的验收与伪因果防线

1. 新观察默认关闭；新增hook开/关对同一17帧前缀码流、hex PSNR、MD5逐项一致，不能只复用旧5帧开关验收。
2. 每个实际编码干预独立解码且参数一致；只读counterfactual不写真实q/context/budget/search count。
3. stage/tile SSE守恒，原图hash/尺寸一致；相同SSE不等价于相同重建，需同时核对hash。
4. trace键稳定，候选分支分化后的新增/缺失显式标记；不得强行跨不同入口做局部J比较。
5. 观察与工具关闭实验均不用于速度结论；临时重建图或误差图若另有需要，留在本地，不默认上传原始视频。

8. 不以源码存在某通道代替本次实际触发证据；不因关工具后单点改善就建议正式关闭工具。
