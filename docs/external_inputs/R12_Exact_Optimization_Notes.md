# R12 不改变编码逻辑的精确复杂度优化

## 1. 目标与核查边界

固定读取提交：`e43a8889ebbc22f4586172bedf96d61d60c38365`。目标是保持同一R12模式的因果输入、预测动作、量化搜索结论、语法/概率状态及最终码流，减少重复纯计算。不是继续修改候选集、专家集、guard、QP范围或验证邻域来换取速度。

本次实际读取了 `TsR10Prediction.h`、`TsR9Prediction.h` 和 `ContextModelling.cpp`。R12生产头文件在此前该快照未能读取，因此下面是可用于R12的等价改造方案，不将所有机会宣称为R12已确认存在的实现缺陷。本次没有修改codec，没有运行视频或正式计时。

## 2. 已有优化与具体新机会

### 已有优化不能重复算成新增空间

- `r10Experts` 已经通过一次整数 `rateDecision` 共享B/R2-2与原C/R3的候选评估。
- `r10PredictionTS` 已先比较CI，只对CI并列最小专家生成外层CF损失。
- `tsLocalExperts` 已有默认关闭的CG动作缓存，按位置、完整五邻域和pool命中，并由快照/CG切换清空。

A本身仍使用CF，不能因为外层出现唯一CI赢家就把A换成CI或取消快照。

### 源码支持优先检查的冗余

`r10PredictionTS` 在当前完整动作全部相同时，仍先计算历史损失，最后 `r10Select` 才返回。注释说明是为了观察真实V。正式路径只需要动作时，可以在所有可能动作一致后提前返回；诊断字段仍由完整观察路径计算。

`r10Experts` 只消费 `r9Decision(...).action`，而后者还生成父级R8对照、base、score和baseScore。应考虑动作专用纯函数与诊断函数分离。编译器可能已经删除部分无副作用冗余，是否真的耗时需profile或生成代码确认。

CoeffCodingContext构造时重新分配/填写TU大小的逆scan表；其几何可移到共享只读模板，不必每个RDO上下文重复构造。

## 3. 精确代价缓存与评分代数

原k=0幅值映射对非零a只会用到 `C(1)`、`C(a)`、`C(a+1)`。在同一冻结cost模型下，n个样本只有m≤5个不同正幅值，通用上界只需2m+1≤11个不同cost求值；P0没有超过最大样本的候选时还可跳过最大幅值的C(a+1)。

令w_j为原规则规定的权重（不能趁优化改权重），则：

```math
S(p)=\sum_jw_jC(M(a_j,p)),\qquad S_0=\sum_jw_jC(a_j),
```

精确等价于：

```math
\boxed{S(p)=S_0+
\sum_{a_j<p}w_j[C(a_j+1)-C(a_j)]
+\sum_{a_j=p}w_j[C(1)-C(a_j)]}.
```

该式不要求C单调，对冻结fractional整数表也成立。按不同幅值排序，累计其权重和与前缀差值，每个候选只取前缀项和命中项。候选范围、Current优先、规范化p=0/1与原tie次序保持不变。

A的identity-trim罚项同样可写为：

```math
B(p)=\max\{0,\max_{v<p}[C(v)-C(v+1)],
C(p)-C(1)\ \text{当p在支持中}\}.
```

故可用前缀最大值精确计算。重复幅值能合并求和，但最大单位置罚项不能乘出现次数。

对B与加权C，共享同一个CI映射/cost缓存，分别累计未加权与加权分数。C仍先找原raw赢家，再计算其相对Current的d_j和full/soft guard。不能把原“raw后guard”改成按guard重选赢家。位置槽位保留，full penalty是max(w_j*d_j)，soft是max(d_j)，不能把相同幅值的权重总和当成一个位置。

CI与CF、不同directNonzero分类的CF必须区分缓存。无合法更大候选时不要额外访问C(a_max+1)。优先落地小表共享，再测前缀算法是否值得：n≤5，排序/表结构开销可能抵消节省，不保证理论形式更快就实际更快。

## 4. 完整决策等价的求值重组

### 4.1 动作快路径

只有确认当前所有可能被选择的规范化完整动作一致，且调用方无需完整诊断字段时，才跳过历史验证。R12-3必须考虑D，不可只比较ABC。一般动作含保护参数时比较(p,k)，不是只比p。

若原专家索引/loss/trace等被观察，保留完整观察路径或重建相同统计。合法输入的必要检查保持，不能用减少异常检查来冒充算法收益。

### 4.2 延迟外层CF

按每个原模式的精确tie、near、LOO条件，只计算真正被允许挑战的专家CF。R10已有此类优化，应核对R12是否继承，不要重复实现两套。

这只延迟外层loss，不延迟A产生动作需要的CF，更不跳过CABAC状态更新或RDOQ CG回放。

### 4.3 只缓存真正纯函数结果

缓存键/作用域覆盖位置与可得性、完整h、专家pool/模式、Rice、动态范围及概率快照。RDO分支复制、前缀编辑、CG清零和快照改变必须失效。缓存动作不需要把目标a_i作为预测输入；缓存历史loss则还要包含已知目标幅值及其cost条件。

一个稳定CG遍历中，原结构最多约6M次位置专家组查询；缓存可让每个位置/同状态只计算一次，至多M组。M由实际CG几何决定。这不是六倍整编码加速：实际还有提前返回、缓存匹配成本，RDO还会产生不同状态。

若TS-RDOQ同一位置的多个q_i候选只改变当前值，而h_i、Rice及冻结快照不变，预测动作可外提一次。更早系数或状态改变则重算；不能将前一次trial结果跨状态直接复用。

### 4.4 静态几何预计算

按真实TU尺寸、CG尺寸和scan身份预计算逆scan与五邻域索引、边界及同CG关系。动态非零判断仍从当前coeff读取。多线程仅共享初始化完成的只读模板，不为全部理论尺寸无约束分配大表。

## 5. 次级优化及禁止事项

同一历史行各专家的映射幅值相同，其CI/CF cost相同，可只查一次或消去公共常数；仍保留validation、位置、n_eff和LOO身份。仅CI相等不足以消去CF信息。含D的模式不能只对ABC消去后遗漏D差异。

候选累加非负cost时，若部分和已经**严格大于**某个完整可行候选的相同目标，可证明其不会获胜，从而停止计算。等于时不能删，因为CI平局可能被CF/tie规则打破。对near/LOO复合选择器须另证挑战集合不变，不能照搬普通argmin剪枝。相对节省d_j可正可负，不能直接以当前部分和当单调界。

以下都不属于本计划：减少五邻域或专家、修改near阈值、用CI近似CF、CF降精度、跳过CG概率回放、全CG累计代替空间V0、跨快照复用CF、按Class或QP禁用、改变原候选平局。

整数重写需足够宽的有符号中间量、边界与移位检查，不依赖溢出；不以浮点近似替代既有定点结果。源码冗余可能已被编译器消除，仍须实际计时。

## 6. 实施与验收

优先对R12-11做独立工程版：

1. 动作/诊断路径分离与正确提前返回；
2. 小cost表、共享B/C与A评分的精确代数；
3. 动作缓存/同位置量化候选循环外提；
4. 共享scan模板；
5. 最后再评估复杂的证明型剪枝。

每项单独开关，仍运行同一个R12模式，不登记新的收益实验。保留原二进制以配对对比。

验收：纯函数score/guard/tie/action一致；真实Writer、Reader、estimator、RDOQ/replay最终q和context一致；同R12模式新旧完整码流字节一致并交叉解码；仅重建hash相同不够。需确定性配置，无基于实际耗时的自适应搜索终止。

任何RD变化先排查正确性或运行身份，不解释为等价优化的新收益。先用已有C/E短段，不因每个工程开关重跑BCE。关闭统计、同机配对计时，分别报告优化后R12/原R12，以及优化后R12/Current；两种对照不能混淆。

## 7. 本次数学参考测试

本次在容器实际执行纯Python参考：21,552组评分输入；85,187个候选score与identity penalty；255,561次guard接受比较；5,000次公共行消去的选择一致性检查，全部通过。包含小幅值整数cost及随机非单调整数表。P0测试中每模型最多实际读取10个不同cost值。

这些只验证代数和有序CI/CF选择，不验证C++溢出、原生scan、完整R12实现、CABAC同步、视频码流或速度。本次没有生产补丁。完整说明、参考脚本和validation.json在本次会话的 `R12_Exact_Optimization_Bundle.zip` 中；本仓库文件是方案摘要，不单独作为完整运行环境。
