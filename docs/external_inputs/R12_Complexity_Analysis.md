# R12各组复杂度与编码耗时风险

## 1. 结论与证据范围

读取快照：`c071ad50d2ffdbe2663570c7029616c0bba05115`；分支 `experiment/ts-predictor-study`；规格 `R12-POS-01`。

**相对R10-3，R12多数组只是有限局部计算的增加；相对Current，所有R12都继承了多专家、历史验证和TS-RDOQ概率回放的总成本。两种比较不能混为一谈。**

R12-11的部分删除本身不需要浮点、除法或额外完整TU重建，和R12-7/8属于同一复杂度类别；更值得关注的是加权C专家与原B/C共享计算的关系、重复调用以及统计开关。

目前不能根据已发布的BD-rate推断编码时间增加1%、5%或10%。本次能核对实现/验收文档及RD台账；`rd_points.csv`字段不含编码和解码耗时。文档指定的 `source/Lib/CommonLib/TsR12Prediction.h` 在该快照仍返回404，目录查询也未发现该文件；因此下面是按已推送实施说明和公式作出的结构分析，**不是生产二进制的逐函数剖析或实测速度排名**。验收文档早于正式RD结果，其“尚无真实序列结果”不能用来否定后来已有的336个CE实测点，但其中确实没有正式同机时间基准。[S1–S4]

本次未运行编码、解码、生产代码基准或模拟速度测试；未修改源码、实验编号、BD数据或资源门槛。

## 2. 主成本来自共同框架，不只是每组新公式

R10-3及R12的共同专家为A=R8-12、B=R2-2、C=R3-1（7/8/11/12替换C）。当前位置计算专家动作；需要验证时，至多五个同CG历史目标各自再用自己的更早邻域计算专家动作，然后评价已知历史幅值。B与原C可共享整数候选评估，A仍使用冻结fractional成本。[S1,S3]

这里是局部五邻域验证，**不是整个CG前缀累计**，也不是递归调用完整专家选择器。不能改成三个全CG累计损失就声称等价加速。

设N为一次TU处理的系数数，V≤5为验证目标数，n≤5为每个专家的非零支持数，K≤6为P0候选数，E=3（模式3临时评价第四个简单Current动作）。一次查询的结构可写为：

```math
T_{query}\approx(V+1)T_{experts}+O(VE),\qquad
T_{experts}=O(nK).
```

固定模板下，一次完整TU遍历为O(N)，但常数可能不小：一次query可能包含当前位置加最多五个历史目标的专家组计算。早退、支持不足以及共享cost会降低实际工作量，以上不是每次都达到的调用次数。

编码时间还取决于：多少个TU候选尝试了TS、每个候选中预测器被调用几次、每CG的finalized概率回放、最终Writer多遍调用以及改变q后引起的模式搜索路径变化。**最终被选中TS的面积比例不是编码端尝试TS的计算占比。**

## 3. 各组相对R10-3的增量

下表“低/低至中”指复用共同计算时的局部结构增量，不是完整编码时间测量。

| R12 | 新增工作 | 结构增量 | 主要风险 |
|---|---|---|---|
| 1 | CI gap比较；near候选参与CF | 低 | 若基线延迟CF，新增near会多计算部分CF；若已算齐则没有同等新增cost求值 |
| 2 | 只让R3作near挑战 | 低 | 开放范围较1窄，不代表实测必更快 |
| 3 | D=max(L,U)及其历史CI/CF损失 | 低至中 | D很便宜，但ABC相同而D不同会丢失原三专家快捷返回 |
| 4 | 合计减去单行，收集合法删一最优集合 | 低（复用矩阵时） | 不应每删一个样本就重新运行专家或RDOQ |
| 5 | L/U子集CI比较，必要时回完整集合 | 低 | 若先构建完整矩阵，direct-first不会自动减少计算 |
| 6 | near集合与LOO集合取并集 | 低；与4同量级 | 不应分别完整运行2和4再组合 |
| 7 | 新C的加权候选累计与raw选择 | 低至中 | 原B/C最终决定不能继续共用；应共享底层整数cost |
| 8 | 7的候选排序加完整加权最大贡献 | 低至中；与7/11同类 | 额外最多五项贡献比较，不是新一轮量化搜索 |
| 9 | 既有验证CI、CF各按位置乘1/2 | 低 | 不应复制样本来实现权重2，不增加验证位置 |
| 10 | 只给原CI平局中的CF加位置权重 | 低 | 条件范围较窄，实际是否延迟CF须看生产实现 |
| 11 | 加权C与未加权最大正贡献 | 低至中；接近8 | 半删除可精确用整数表达；主要成本在新C排序 |
| 12 | 7的加权C加9的外层加权 | 低至中 | 应只算一次专家和矩阵，不是分别完整调用7、9 |

没有一组在定义上新增一套完整TU重建/RDO候选，区别于R9-11/12一类显式量化编辑复核。但它们仍会通过既有rate模型改变q、CG清零、TS获选和后续编码路径。[S1]

### 3.1 R12-4/6不是O(N平方)的全量重跑

预先缓存每个历史目标、每个专家的损失ell(e,j)，再使用：

```math
L_I^{(-j)}(e)=L_I(e)-\ell^I_{ej}.
```

合计已知后至多V×E=15个删行分量，再比较各删一情景的最小值。无需重读所有支持、重新产生候选或重新量化。若使用朴素重算版本，会多出重复计算；没有理由把这种额外成本当作算法必须承担的成本。

### 3.2 R12-3不是第四套完整搜索，但可能更常进入验证

Current动作只需max(L,U)，历史目标最多再补五次CI与按需CF计算。不过模式3不能只因ABC当前动作相同就提前退出，必须考虑D。原生验收专门覆盖了“ABC相同而D不同”的情况。[S2]

因此它的风险在快捷返回率，而不是max运算；是否比7/11更快需要调用计数，不能给出绝对排序。

### 3.3 7/8/11/12的加权C破坏了哪些共享？

原B=raw和C=guard共用一次整数候选评估；加权C需要不同的候选分数和排序，不能直接拿B的winner作为C的winner。

但对同一邻域和同一候选p，底层 `c_I(M(a,p))` 仍可共用：一次循环同时累计B的等权分数和C的加权分数。实施说明已有共享映射cost小缓存，但本次未取得对应生产头文件，不能认证共享具体做到何种程度。[S1,S3]

n≤5、K≤6时，单邻域至多30个样本—候选分数组合。加权C相对旧共享决策多出一套加权累计；一次query若当前位置和五个历史位置都达到上限，则对应至多180项额外加权分数累计，另有少量max/比较。**这不是180次完整预测、更不是180次RD或CABAC编码。** 实际支持数与早退会缩小该数量。

## 4. R12-11的部分删除不贵

相同raw候选下：

```math
G_w=2d_L+2d_U+d_D+d_{LL}+d_{UU},\\
H_{full}=G_w-\max(0,2d_L,2d_U,d_D,d_{LL},d_{UU}),\\
H_{soft}=G_w-\max(0,d_L,d_U,d_D,d_{LL},d_{UU}).
```

本规格中“近邻删除一半”已经由权重2与惩罚1精确表示，**不用先乘浮点0.5，更不需要除法**。full与soft只是最多五项max的输入不同；两者同阶且属于相近的算术工作。raw少一个guard检查，也不代表全编码一定更快，因为早退、动作一致性和闭环路径可能改变。

因此，不能因为11包含“加权＋部分删除”就判断它明显比7/8贵，也不能因为公式短就宣布它对Current几乎零开销。

## 5. 为什么O(N)仍可能带来明显时间增加？

相对R10-3，令f为基线总时间中受影响预测/验证链路的时间占比，k为相同工作负载下该链路的耗时倍率，delta为候选数量与闭环搜索改变带来的归一化剩余项，则：

```math
\frac{T_{12}}{T_{10}}\approx1+f(k-1)+\delta.
```

下面仅为敏感性算术，delta暂取0，**不是已测或预测的R12时间**：

| 假设f | 假设k | 对总时间的影响 |
|---:|---:|---:|
| 2% | 1.5 | +1% |
| 10% | 1.5 | +5% |
| 20% | 1.5 | +10% |

没有f、k和真实调用次数，就不能从代码有多少行、最终TS使用比例、某组RD点与基线相同的数量推断总时间。

相对Current还需额外计入原本没有的多专家及因果验证框架、冻结概率模型、RDOQ finalized-CG回放等成本。因此R12-11相对R10-3很接近，也可能同时与Current存在显著时间差。应同时测T12/T10和T12/TCurrent。

解码器也必须选择相同公共动作，不是免费；但没有编码端大量候选试算。其相对总时间的比例不能由编码时间直接推算。

## 6. 当前最需要排除的计时混淆

### 6.1 统计默认值不同

R10实施文档写明：核心统计默认关闭，但正式批量封装默认开启。R12文档写明统计默认关闭。[S1,S3]

所以不能拿未核对环境的两轮服务器耗时直接比速度。开统计时可能额外重算专家、计算target regret、执行shadow和写日志；替换C的模式还要独立计算原R10-3用于对照。活动稀少也不保证这些观察成本稀少。

计时前按各模式实际支持的参数显式关闭TS_R10_STATS、TS_R12_STATS和相关trace/shadow，检查有效banner及任务指纹。不能只看编译宏或推定默认环境未变化。

### 6.2 缓存模式不对称

R10已有当前CG动作缓存，默认关闭；R12实施明确与R10_CACHE互斥。[S1,S3] 比较时先统一关闭缓存，不能将cache-on的R10和cache-off的R12差异全部归因于新公式。

若为R12移植缓存，应缓存每位置纯专家动作，并保持原空间验证集合。键须覆盖支持值、专家模式和概率快照/CG生命周期；历史目标损失使用当前已知目标重算。RDO分支、q编辑、CG清零、快照变化必须安全处理。不能只用scanPos命中，也不能把全CG前缀累计称为等价缓存。缓存检查和内存访问本身有成本，必须实测净收益。

### 6.3 热循环重复初始化与CF计算

小数组、loss矩阵、候选集尽量固定容量；逆scan表只在相应TU/上下文初始化阶段构建，不在每个query重新分配。若在每个query重建长N的表，单次TU就可能出现O(N平方)的实现性开销，而非公式本身的需要。

外层CF可以在确定整数竞争集合后按需计算。**A专家生成仍需CF，不能因外层整数唯一赢家就跳过A需要的概率数据。** 统计字段若要求完整观察，应仅在观察路径补算，不污染release热路径。

## 7. 内存规模

若局部CI与CF各用64位，5历史位置×4专家×2类cost为320字节；三专家为240字节。这只是loss矩阵，不是整个上下文内存。还要计入候选、支持几何、冻结表和TU逆scan索引（如int32索引为4N字节）。缓存则随实际CG长度增加，不硬编码16。

新增公式本身不需要另一张全帧图像或额外重建缓存，内存容量通常不是第一风险；但热循环动态分配和上下文频繁复制可能影响CPU耗时。不能据局部矩阵小就忽略这些管理成本。

## 8. 最省资源的实测安排

先解析已有相同机器/设置的编码日志：内部encoding CPU秒与wall秒、解码秒、统计/缓存有效状态、线程、帧范围、二进制SHA。只有设置可比才作正式时间比。台账pass和BD数值不能认证这些身份。

若需新增计时，首轮只比较 **Current、R10-3、R12-11**。选固定C/E短段如PartyScene、BQMall、Johnny，高低QP各一个；不额外开启Class B长测。短段结果先用于识别热点，不直接登记为完整CTC复杂度。

同机同核心/线程、同编译优化和输入区间，关闭观察和其它编码竞争任务；交替运行候选与对照并重复，记录各点中位时间和离散程度。报告每点T12/T10、T12/TCurrent、最慢点，以及明确权重的汇总；编码与解码分开，排队、编译和批处理等待时间不混入编码时间。

再对R12-3与4/6中的一组做同条件计时，即可覆盖简单D、LOO以及加权C三种主要增量，不必重跑全部12组BCE。

需要性能计数时单独采样：r12PredictionTS查询数、专家组生成数、有效V、CI/CF求值次数、RDOQ回放次数、模式3丢失快捷返回的次数、cache检查及命中率。最终Writer活动人口不能替代编码搜索里的这些调用次数。

## 9. 实际决策

优先测量并优化R12-11与主线的共同热点，而不是因其部分删除公式放弃它；R12-3重点检查提前返回变化；4/6重点保证复用loss矩阵。9/10的权重算术本身不应成为主要瓶颈。

这些判断不改变既定目标：同一版本既要满足完整B≤−0.04%、BCE≤−0.10%，又要报告真实编码/解码时间。当前没有足够时间证据认证哪组可忽略开销，也没有依据认定R12必然造成很大的编码时长增加。
