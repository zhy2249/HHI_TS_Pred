## 1. 结论和数据边界

## 2. 计算口径

每个分量用四点PSNR—log(整码流码率)的PCHIP曲线，在两版本共同质量区间积分、不外推，然后计算 `(6*BD_Y+BD_U+BD_V)/8`。CE七序列、C四序列、E三序列分别等权。所有百分数均是BD-rate百分数，例如−0.1表示−0.1%，不是−10%。

直接版本增量重新积分两条曲线，不用两个“对Current”的BD-rate相减。质量分段保持完整四点曲线，以Current的QP32和QP27对应PSNR切割低/中/高区间，不是所谓“单QP BD-rate”。B的三点诊断只用双方共同实测QP27/32/37、重新拟合，不冒充正式四点CTC，也不与四点CE混合。

相同RD点指保存精度下码率及Y/U/V PSNR四字段相同，不等于码流逐比特一致或算法从未触发。删一序列检查是样本构成敏感性，不是重编码或独立统计认证。开发集经历多轮选优，不宜将微小均值差直接视为泛化结论。

## 4. R12-11：保留为候选，但不要因第一名就直接替换主线

### 4.1 净改善来自哪里

| 序列 | R12-11 / Current | R12-11 / R10-3 |
|---|---:|---:|
| BQMall | +0.064089% | +0.022911% |
| BasketballDrill | −0.322163% | −0.014148% |
| PartyScene | −0.340097% | **−0.096506%** |
| RaceHorsesC | −0.163472% | +0.057588% |
| FourPeople | −0.025775% | 0 |
| Johnny | −0.300210% | 0 |
| KristenAndSara | −0.035277% | 0 |

相对R10-3是2条改善、2条退化、3条相同，非零变化集中在C。去掉PartyScene后，六序列直接平均为 **+0.011059%**；任意删一序列的范围为[−0.014624%, +0.011059%]。这不意味着应剔除PartyScene，而是当前净增量对内容组成敏感。

19/28个RD点与R10-3相同；E的12点全部相同，七条序列的QP37也全部相同。九个改变点是C四序列的QP22/27以及PartyScene QP32。不能据此认为未变点无内部活动，但当前没有看到E低质量薄弱区被修复。

### 4.2 不是单一插值方法制造的方向

R12-11直接对R10-3：PCHIP −0.004308%、三次多项式 −0.003346%、分段线性 −0.003693%。主口径固定PCHIP，不按结果挑插值。改善方向在这三种检查中一致，但它不能解决内容依赖和闭环敏感性问题。

直接分量增量为Y −0.012478%、U +0.055301%、V −0.014897%。三个分量共用整码流码率轴，而且Y的模式/重建可以影响色度；不能将这些数值当作三个predictor各自直接造成的比特份额。

### 4.3 与“同权重的两种删除极端”比较，证据更有说服力

| 比较 | CE直接增量 | C | E | 改善序列 | 任意删一后的平均范围 |
|---|---:|---:|---:|---:|---:|
| R12-11 / R12-7 | −0.034038% | −0.063811% | +0.005658% | 5/7 | [−0.052251%, −0.024629%] |
| R12-11 / R12-8 | −0.043016% | −0.057596% | −0.023575% | 6/7 | [−0.051238%, −0.029915%] |

三组用同一权重W=(2,2,1,1,1)，相同加权raw候选，只改变C内部接受规则。令d_j为候选相对Current的单位置节省，则：

```math
G_w=2d_L+2d_U+d_D+d_{LL}+d_{UU}.
```

R12-7只要求G_w>0；R12-8要求：

```math
G_w-\max(0,2d_L,2d_U,d_D,d_{LL},d_{UU})>0.
```

R12-11要求：

```math
G_w-\max(0,d_L,d_U,d_D,d_{LL},d_{UU})>0.
```

这相当于直接邻居的最大正贡献只削去其加权贡献的一半，较远位置完整削去。它保留部分位置相关的重要证据，同时不完全取消单样本限制。

在本批数据中，部分删除优于这两个极端；但还不能断言“直接邻居必然更可靠”或“半删除最优”。尤其11相对7的E均值稍差，优势主要来自C。专家C的局部接受集合虽有包含关系，外层验证和RDOQ闭环收益并不单调。

## 5. 原near-tie与外层加权各得到什么

### 5.1 R12-1～6没有证明near-tie能继续带来平均收益，但范围收缩确实避免了R11的大退化

1/2将CF判断扩到整数差一单位的情况，分别对R10-3退化+0.008126%/+0.010679%。这不证明CF在所有非平局处不合适；它只说明“差一个代理量子”本身还不够成为可靠的切换依据。

3把Current限制在双边near条件中，直接差距只有+0.001363%，比旧全局加Current的结果接近主线。但目前没有新增B数据，不得把它命名为“B修复版”。可保留为11之外的机制不同候选。

4/6直接差距为+0.004461%/+0.004160%，低质量端却比R10-3改善，高质量端损失。4和6有21/28个相同RD点，6直接对4仅−0.000213%。预算紧时不必同时给二者铺开B。

1/2/3/4/6在E仅改变KristenAndSara的QP22，其余11点未变；11则E全部未变。当前数据尚未显示这些受限决策真正改善了E低质量端。需要用同一实际轨迹上的候选/选择/remap/提交计数区分“没有开放机会”和“开放了但最终影响抵消”。

5的L/U硬优先直接退化+0.041893%，没有序列直接改善（1条相同）。这不支持把远邻证据一律覆盖掉。

### 5.2 外层软加权优于硬优先，但仍不优于原等权验证

9相对5改善−0.022539%，C/E均改善；10相对9改善−0.007574%，但对R10-3仍退化+0.011407%。因此“保留远邻并软加权”比本次硬优先更合理，但没有证明外层位置权重普遍有利。

12相对7退化+0.003371%，相对9退化+0.014559%。不要因为内外都利用位置信息就预期两者可以相加。四角的100×log-rate交互为负（约−0.015818），只表示相对简单可加模型有交互补偿，不能抵消其仍落后主线的事实。

### 7.1 R10-3只剩一个QP22，补它比再铺多组B更有决策价值

R10-3现有19/20个B实测点，BasketballDrive QP22已补齐。四点完整序列为：

| Cactus | −0.206515% |
| BasketballDrive | +0.041944% |
| BQTerrace | 不完整，缺QP22，不填补 |

B四条完整子集均值−0.017388%，这四条加CE七条的11序列子集均值−0.105630%。两者都不是完整B/BCE。

令x为BQTerrace最终四点BD611，则：

```math
BD_{BCE}=\frac{11(-0.1056302869)+x}{12}.
```

因此已有固定11条结果下，要达到完整BCE≤−0.10%，仅需：

```math
x\le-0.038066844\%.
```

这是缺失曲线需要达到的阈值，不是BQTerrace QP22本身的码率要求，也不是预测。其已测27/32/37区间为−0.093694%，但三点曲线不能保证四点最终仍低于该阈值。应优先补这个唯一缺点，并核对程序/帧范围身份，不作anchor填补。

## 8. 下一步优先级：少量确认，而非再开一轮大矩阵

**第一，补齐R10-3的BQTerrace QP22。** 仅一个编码点即可消除当前完整BCE目标判断的关键缺口。不要仍将“约−0.095%”作为固定真实总平均。

**第二，保留R12-11做第一B候选，R10-3保持主线对照。** 11已通过CE≤−0.15%的资源门槛，且其内层机制有匹配证据。先MarketPlace/BasketballDrive/Cactus的QP27/32/37共9点；不要直接跑所有R12的B。

**第三，R12-3作为次优先、机制不同的候选。** 它的CE只略差，符合受限Current挑战的研究目的，但没有证据保证B更好。4与6优先择一保留低质量端观察，暂不同时扩大B资源。

各候选达到BCE≤−0.10%需要的完整B平均：R10-3≤−0.021524%、R12-11≤−0.015419%、R12-3≤−0.023161%、R12-4≤−0.027820%、R12-6≤−0.027443%。这些只是给定CE后的条件要求，不能视为已实现结果。

通过B前不因为11的微小增量就用它覆盖所有基线。CE未过门槛的其它版本不启动完整B；仍可保留其局部互补和结构证据，不永久判死。

研究上，先判断11的改变来自“新加权raw候选”还是“full拒绝而soft接受”的位置，再决定是否进行有限的条件化。对7/8/11应在同一真实轨迹上分别统计near/far最大贡献位置、G_w与两种penalty、C动作、外层被选、目标代价和最终提交。不得根据最终测试序列倒推一个Class/分辨率/QP开关，也不立即扫描1/3、2/3等多个删除系数。

## 9. 文件与可复现性

- `analysis_input.csv`：标准化数值输入，包含当前结果与本会话已有历史对照；状态保留，不填缺失。
- `r12_rd_points.csv`：本轮336个数值点；`b_new_points.csv`：新增B点及缺失占位。
- `analyze.py`：PCHIP、直接比较、质量分段、相同点、插值敏感性与四角交互。
- `add_b_points.py`：生成已核验B数值及同覆盖诊断，不请求网络。
- `computed/`：全部派生表与审计记录。
- `R12_Results.xlsx`：公式汇总和可筛选明细，单位标注为百分数值。

```bash
python analyze.py --input analysis_input.csv --out computed
python add_b_points.py
```

需要Python、numpy、scipy；不运行编码器。`build_input.py`为本次数值转录构建脚本，通常无需运行；若运行，随后必须运行`add_b_points.py`恢复最新B输入。不得把旧输入中未用于本次比较的历史版本误当新结果。
